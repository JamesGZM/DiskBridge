# 架构

DiskBridge 是单一的 macOS Swift 可执行程序，应用包通过不同启动参数承载三种入口：原生管理窗口、`--background` 菜单栏以及 `--agent` 后台任务服务。没有 Python 进程、第三方守护程序或网络监听。

| 文件 | 职责 |
| --- | --- |
| `Main.swift` | AppKit 生命周期、窗口、菜单栏、启动授权引导 |
| `Views.swift` / `Model.swift` | SwiftUI 页面、交互状态和本地任务请求 |
| `Core.swift` | 原子 JSON、任务进度、操作锁、系统命令、目录清单与 SHA-256 |
| `Catalog.swift` | 按应用标识和容器扫描应用与候选数据目录 |
| `Migration.swift` | 单目录迁移、切换、挂载、还原、原件清理的持久检查点 |
| `Service.swift` | 本地任务收件箱、读取队列、串行写队列、多目录任务与历史 |
| `Jobs.swift` | 自动挂载、等待重试、自动打开去重、外置副本核验清理 |
| `Installer.swift` | 用户级登录任务登记与本地数据目录定位 |

## 任务与并发

界面在私有运行目录提交 JSON 请求，后台保存阶段、进度与结果。后台有独立实例锁；数据操作使用根目录的 `flock`，避免后台与手动任务同时切换数据。等待硬盘或应用退出时不会一直占用根操作锁。

需要改变目录或配置的任务在串行写队列执行；只读查询使用独立读取队列。自动挂载按应用短时持锁，部分应用失败时保留各项结果。

## 迁移顺序

1. 确认应用及其他账号窗口已退出，验证目录范围与目标外置盘。
2. 在目标盘建立 APFS 稀疏镜像，记录任务身份。
3. 将全部选中目录分别复制，核对内容清单和 SHA-256。
4. 校验原件未变化，保留原目录，再建立保护挂载点。
5. 挂载并核对标记及卷 UUID，等待用户在应用内验收。
6. 验收后启用自动挂载；原件清理仍是独立任务。

还原先复制并校验最新工作数据，再卸载并切换回内置目录。外置副本默认保留。中断任务通过已保存阶段恢复，不仅凭目录名称判断身份。

## 系统集成

使用系统自带的 `diskutil`、`hdiutil`、`ditto`、`launchctl` 等工具，并以独立参数调用，避免将路径交给 shell 解释。新版系统可使用 `diskutil image attach`，旧系统保留 `hdiutil` 兼容路径。

登录任务标签保留早期版本的 `com.local.appdatamount` 名称以兼容已有安装。任务是否属于当前数据根目录必须通过元信息检查，不能覆盖其他实例的登录项。

启动权限检测由原生后台执行，避免仅凭终端进程可以读取目录就推断后台也已授权。授权由用户在系统设置完成。
